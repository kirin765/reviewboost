## Codebase Patterns
- Keep Supabase schema changes in both places:
  1) canonical `supabase/schema.sql` (fresh setup + backfill section), and
  2) timestamped idempotent SQL under `supabase/migrations/` for replayability.
- For uniqueness on nullable external IDs, use partial unique indexes:
  `create unique index if not exists ... where <column> is not null`.
- Lightweight schema tests can be repository-level SQL contract checks via Node scripts when DB integration test infra is not yet present.
- For TS utility unit tests without a dedicated test runner, use a small Node script with `typescript.transpileModule` + dynamic `import(data:)` and `node:assert/strict`.
