## Codebase Patterns
- Prefer a dedicated normalization layer for SEO/static-build data (`raw` -> `normalized`) so route generation/sitemaps operate on one trusted in-memory contract.
- Use deterministic IDs derived from source identity and canonical text keys to keep static path output stable between builds.
- Surface schema errors with `[collection][index].[field]` paths for fast data-fix loops during CI/build-time validation.
- For static SEO routes, resolve slug collisions in a post-processing pass (`assignUniqueSlugs`) keyed by stable entity IDs so route output remains deterministic even if source ordering changes.
